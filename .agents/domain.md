# Domain Docs

This repo uses a single-context domain documentation layout.

Before exploring domain-sensitive code, read these if they exist:

- `CONTEXT.md` at the repo root
- `docs/adr/` for architectural decisions relevant to the area being changed

If these files do not exist, proceed silently. The domain-modeling workflow can create or update them later when terminology or decisions are resolved.

Use the vocabulary from `CONTEXT.md` when naming domain concepts in issues, specs, refactors, tests, and implementation notes.

If a proposed change contradicts an ADR, surface the conflict explicitly.
